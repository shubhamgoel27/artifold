# v0.6.1 — Move-to-Trash (un-index by deleting)

**Status:** done (2026-06-07). 18/18 tests pass.

**Trigger:** "in the UI, can we add an option to delete/un-index a file, this is for those cases for e.g when multiple iterations of a file report are generated, but in the artifold ui, id like to keep only the best one"

## Design notes

- **Move-to-Trash, not unlink.** Misclicks on the trash button shouldn't destroy an hour's work. Uses macOS Trash / Linux Trash / Windows Recycle Bin via `send2trash`. Recoverable via Finder → Trash → Put Back.
- **Per-version, not per-project.** The user's case is iterations grouped under one project — they want to nuke N-1 of them. Each version is independently trashable via the detail-pane version switcher.
- **Confirmation modal** (not Gmail-style undo). Modal shows file path + size + "this is the only version" warning when applicable. Click to confirm — then watchdog catches the deletion, debounced rescan runs, SSE pushes the update, UI refreshes.
- **Provenance preserved** — the hash-keyed metadata stays in provenance.json so restored files auto-reattach to their old tags/source/intent.

## Multi-file note

Trashing a multi-file artifact's index.html leaves sibling CSS/JS on disk (orphaned but harmless). User can drag the whole dir to Trash for full cleanup. Future v0.6.2 could add a "trash whole project dir" advanced action.

## Files

- new `artifold/trash.py` — `trash_file(path) → (ok, msg)` with safety rails (rejects dirs, missing files, etc.)
- `artifold/serve.py` — `POST /trash {path}` endpoint, validates against configured roots, triggers immediate followup scan
- `artifold/cli.py` — `artifold trash <path> [-y]`, confirms by default
- `artifold/template.html` — trash icon button in detail header, confirmation modal with destructive red action
- `pyproject.toml` — added `send2trash>=1.8` dep
