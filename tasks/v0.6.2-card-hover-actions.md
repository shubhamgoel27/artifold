# v0.6.2 — Card hover actions + defensive JSON error

**Status:** done (2026-06-07). 18/18 new tests + 18/18 v0.6.1 regression all pass.

**Trigger:**
1. User reported "Trash failed: Unexpected token '<', '<!DOCTYPE'... is not valid JSON" when clicking the detail-pane trash button. Root cause: their `artifold serve` was started **before** v0.6.1 — the in-memory module didn't have `/trash`, so the request hit the default 404 handler which returns HTML. Browser's `.json()` parse failed with the unhelpful error.
2. User wants per-card hover actions: open-in-new-tab (top-right) + trash (bottom-right) on the main homepage grid.

## What shipped

### Defensive `postJSON` helper (template.html)
- All POST endpoints (trash, export-pdf, share) now go through it.
- On non-JSON response: throws `Server returned <code> (non-JSON). Restart your `artifold serve` to pick up new endpoints.` instead of `Unexpected token '<'`.
- Future stale-server cases self-document the fix.

### Card hover actions (template.html + CSS)
- New `.card-acts` container — absolute-positioned over the card, opacity 0 → 1 on hover.
- `.ca-open` (top-right): open the primary file in a new tab (uses existing `openInNewTab`).
- `.ca-trash` (bottom-right): opens a bulk-trash confirmation modal.
- Tool pill (top-right "claude" badge) fades out on hover so it doesn't clash with the open icon.
- Click-handler exclusion: `.card-acts` clicks don't propagate → don't accidentally open the detail pane.

### Project-level bulk trash (new modal `#modal-trash-bulk`)
- Card trash = "remove this project entirely" — trashes ALL files (primary + versions + variants).
- Modal lists up to 5 file paths with a "+ N more" indicator.
- Confirm button is destructive-red.
- Loops calls to `/trash` (one per file) — no new server endpoint needed.

### Detail-pane trash button (v0.6.1) unchanged
- Still per-version (trashes the currently-selected version, project shrinks to N-1).
- Now uses `postJSON` for consistency, gets the same friendly errors.

## For users on v0.6.1 hitting the JSON error

Just restart your `artifold serve` process (Ctrl-C, re-run). The endpoints have existed since v0.6.1 — your running process predated the upgrade.
