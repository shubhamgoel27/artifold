# v0.5.5 — Watcher robustness + 23× scan speedup + scan transparency

**Status:** done (2026-05-31). 30/30 tests pass.

**Triggered by:** user reporting "auto-rescan feels broken — I always have to
hit Refresh manually."

## Root causes (all 3 contributed)

1. **Scan was 5–10s** (dominated by `rglob('*.html')` walking 45K dirs in `~/work`
   then post-filtering). With a long scan window, any file change made
   during a scan got swallowed by:
2. **Lock-skip silently dropped events** (`_run_scan` failed `acquire(blocking=False)`
   and just returned False with no retry/queue).
3. **`FileMovedEvent` not handled correctly** — editor saves that use the
   atomic rename pattern (`write foo.html.tmp; mv foo.html.tmp foo.html`)
   produced a move event whose `src_path` was `.tmp` → filtered out by
   the `.endswith(".html")` check.

Bonus: the watcher's `IGNORE_NAMES` had drifted from `scan.SKIP_DIRS` —
`artifold` was missing from the watcher list, so every change we made to
the artifold repo itself fired a wasted scan that then ignored its own
content.

## What shipped

### a. SKIP_DIRS canonicalized
- `scan.SKIP_DIRS` is now the single source of truth.
- `serve.py` imports it as `_SKIP_DIRS`; no more drift.

### b. Follow-up queue (no dropped events)
- New module flag `_rescan_pending` (with its own lock).
- When `_run_scan` fails `acquire(blocking=False)`: sets the flag, returns.
- In `finally`, after the lock is released: checks the flag; if set,
  spawns one follow-up scan in a daemon thread.
- Net: events arriving during in-flight scans now ALWAYS produce a scan,
  just possibly debounced into one follow-up batch.

### c. Atomic-rename support
- `H.on_any_event` now considers both `src_path` AND `dest_path` (only
  set on `FileMovedEvent`). Editor saves that rename `.tmp` → `.html`
  no longer get filtered out.

### d. Diagnostic logging
- Each fired event prints `  • watch: <kind> <~path>  (scan in 2s)`.
- Operator can see the watcher working in real time; silent failures
  become visible.

### e. Directory pruning (23× scan speedup)
- `_find_html` rewritten: was `root.rglob('*.html')` + post-filter
  (walks every dir, throws away most). Now `os.scandir`-based recursion
  with SKIP_DIRS pruning before descent, plus max_depth enforced
  during walk, not after.
- Result on user's real `~/work` (45K dirs, 444 HTML files):
  - walk-and-filter:  **5.70s → 0.02s** (285×)
  - full `scan_all`:  **5.35s → 0.24s** (23×)

### f. Doctor transparency for excluded git-repo subdirs
- New `diagnostics.check_excluded_repos()` — walks each root once,
  reports top-level subdirs that have their own `.git` and aren't in
  `allow_repos`.
- New CLI commands: `artifold allow-repo <name>` (add or bare-list)
  and `artifold disallow-repo <name>`.
- New config helpers `add_allow_repo` / `remove_allow_repo` /
  `allow_repos`.
