# v0.7.0: library intelligence: grouping, provenance lifecycle, search, diff

Theme: artifold's most valuable role has become the *memory layer* for
artifact-generating agents (/craft). This release fixes the metadata rot
that was polluting that memory and adds the two queries agents and humans
actually need: "does this already exist?" and "what changed between
versions?".

## Shipped

### 1. Top-level + date-prefix version grouping (scan.py)
Bug: top-level files each formed their own group (`__top__/<name>`), so
`report.html` + `report-v2.html` at root level could never collapse. And
`artifold inbox` date-prefixes every slug, so two iterations of the same
report (`2026-06-09-dsa-concept-bible`, `2026-06-10-dsa-concept-bible`)
looked like unrelated projects. Our own naming convention was fighting our
own grouper.

Fix: all top-level files share one group per root; `_classify` strips the
`YYYY-MM-DD-` prefix before computing the logical stem; same-slug
iterations that all parse as v1 get renumbered chronologically (filename
date, then mtime) so the newest wins primary. Verified on the real inbox:
both known duplicate pairs now collapse into 2-version projects.

### 2. Provenance carry-forward + orphan GC (provenance.py, scan.py)
Bug: provenance is keyed by content SHA1, so any in-place edit orphaned
the entry and `artifold designs` listed `name:"?"` rows forever (37-file
library had a dozen).

Fix: scan records `path` on every entry; when a file's hash changes,
`carry_forward()` migrates the old entry to the new hash (`previous_sha`
chain, old entry marked `superseded_by`). After each full scan,
`provenance.gc()` stamps unseen entries `orphaned_at` and deletes them
after 30 days (so a Trash restore still reattaches). Entries with a live
path (variants, depth-excluded, hand-linked files) are never stamped.
`designs` list mode skips superseded/orphaned entries.

### 3. All four /craft axes extracted (detect.py, cli.py)
`artifold:layout-archetype` and `artifold:signature-device` meta tags now
extracted alongside design-mode/voice-register, stored in provenance, and
exposed in `designs --json`. Embedded-meta extraction also re-runs on
already-enriched entries (backfill on next scan) without clobbering
user-asserted fields. /craft can now rotate all four axes from one call
instead of grepping inbox files.

### 4. Dashboard metadata surfacing (template.html)
Provenance tab shows `notes` (was stored but invisible) and `exports`
history. Design tab shows the four craft axes as flags when present.

### 5. `artifold search` (cli.py)
Keyword search over name / dir / category / tags / topic / intent /
search_text / prompt, weighted (identity > curation > content > prompt),
terms ANDed. `--json` is a stable contract for automation. Wired into
/craft Step 1: before generating, check for an existing artifact and
offer to update it, reusing the slug so the old copy becomes a version,
not a duplicate.

### 6. Version diff view (diff.py, serve.py, template.html)
`GET /diff?a=<old>&b=<new>` renders a standalone page: OLD/NEW live
previews side by side + unified diff of *visible text* (scripts/styles
stripped, block tags as line breaks, so CSS churn stays out of the way).
Detail pane shows a diff button when the selected version has an older
sibling. Paths validated against configured roots.

## Tests
First test suite in the repo: `tests/` covers `_strip_date`, `_classify`,
top-level grouping (3 scenarios), carry-forward, and GC lifecycle
(9 tests). Provenance store isolated via conftest fixture. Run:
`uv run --with pytest --no-project python -m pytest tests/ -q`.
