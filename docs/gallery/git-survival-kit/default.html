Git Survival Kit

12 commands for your first 90 days.

Git has over 150 commands. You need about a dozen to do real work on a team, and one more to get yourself out of almost any mess. Each one below comes with a working example and a recovery tip for when it goes sideways.

01

git clone

Get your own full copy of the repository, history included. Usually the very first thing you do on day one.

Day 1

Example

$ git clone git@github.com:acme/web-app.git
$ cd web-app

# clone into a folder with a different name
$ git clone git@github.com:acme/web-app.git acme-web
  • --depth 1Only the latest snapshot. Faster for huge repos, but no history.
  • -b <branch>Check out a specific branch right away.

Recovery tips

"Permission denied (publickey)"
Your SSH key is not set up with the host. Either add your key, or use the HTTPS URL instead. Test with: 
ssh -T git@github.com
Cloned into the wrong folder?
Nothing is linked to the path. Just move or delete the folder; a clone is fully self-contained.
02

git status

Your "where am I?" command. Run it before and after everything else. It is read-only, so it can never hurt you.

Day 1

Example

$ git status
On branch feature/login-form
Changes to be committed:
  modified:   src/Login.tsx

Changes not staged for commit:
  modified:   src/api.ts

Untracked files:
  notes.txt

# compact view
$ git status -sb
  • -sShort output, one line per file.
  • -bShow the branch and how far ahead/behind the remote you are.

How to read it

Green = staged
Will go into the next commit.
Red = not staged or untracked
Changed on disk, but Git will ignore it at commit time until you git add it.
"HEAD detached at abc123"
You are not on a branch. Get back with git switch main, or keep your work with git switch -c my-branch.
03

git add

Choose exactly which changes go into your next commit. Think of the staging area as a shopping cart.

Day 1

Example

$ git add src/Login.tsx
$ git add src/            # a whole folder

# review each chunk before staging it
$ git add -p
Stage this hunk [y,n,q,a,d,s,e,?]? y
  • -pPatch mode. Stage piece by piece. The best habit you can build.
  • -AStage everything, including deletions. Use with care.

Recovery tips

Staged the wrong file?
Unstage it. Your edits stay on disk. 
git restore --staged notes.txt
Staged a secret or a huge file?
Unstage it as above, then add it to .gitignore so it never happens again.
Gotcha: git add . grabs everything in the current folder, including .env files if they are not ignored. Check git status first.
04

git commit

Save a snapshot of whatever is staged, with a message explaining why. Commits are your undo points.

Day 1

Example

$ git commit -m "Add validation to login form"
[feature/login-form 4f2a9c1] Add validation to login form
 1 file changed, 24 insertions(+), 3 deletions(-)

# forgot a file? add it to the last commit
$ git add src/api.ts
$ git commit --amend --no-edit
  • -m "msg"Message inline. Omit it to open your editor for a longer one.
  • --amendReplace the last commit. Only before you push.

Recovery tips

Typo in the last message (not pushed)?
git commit --amend -m "Better message"
Want to un-commit but keep the changes (not pushed)?
git reset --soft HEAD~1
Already pushed a bad commit?
Do not rewrite shared history. Make a new commit that undoes it: 
git revert 4f2a9c1
05

git log

Read the project's history. Find who changed what, when, and (if they wrote a good message) why.

Week 1

Example

$ git log --oneline --graph -10
* 4f2a9c1 (HEAD -> feature/login-form) Add validation
* 9b1e0d7 (origin/main, main) Bump deps
* 2c7f3aa Fix header overlap on mobile

# history of one file
$ git log -p -- src/api.ts

# search commit messages
$ git log --grep="timeout"
  • --onelineOne commit per line.
  • --graphDraw branches and merges.
  • --author=Filter by person.

Recovery tips

Stuck in a screen with a : at the bottom?
That is the pager. Press q to quit, arrow keys or space to scroll.
Need to know who wrote a specific line?
git blame -L 40,60 src/api.ts
Tip: make a shortcut once and use it forever: git config --global alias.lg "log --oneline --graph --decorate -20"
06

git switch

Create and move between branches. One branch per task keeps your work isolated and reviewable.

Month 2

Example

# start new work from an up-to-date main
$ git switch main
$ git pull
$ git switch -c fix/cart-total

# jump back to the previous branch
$ git switch -

# list branches; delete a merged one
$ git branch
$ git branch -d fix/cart-total
  • -c <name>Create and switch in one step.
  • -Toggle to the last branch you were on.

Recovery tips

"Your local changes would be overwritten"
You have uncommitted work. Commit it, or git stash it, then switch.
Committed on main by accident (not pushed)?
Move the commit to a new branch and reset main: 
git switch -c my-feature
git switch main
git reset --hard origin/main
Older docs use git checkout for this. It still works, but switch does one job and is harder to misuse.
07

git diff

See exactly what changed, line by line. Review your own work before anyone else has to.

Month 2

Example

$ git diff                # unstaged changes
$ git diff --staged       # what you are about to commit
$ git diff main...HEAD    # everything on your branch

@@ -12,7 +12,7 @@ export function total(items) {
-  return items.reduce((s, i) => s + i.price, 0);
+  return items.reduce((s, i) => s + i.price * i.qty, 0);
  • --stagedCompare staged changes to the last commit.
  • --statJust the file list and line counts.
  • -wIgnore whitespace noise.

Recovery tips

git diff shows nothing, but you changed files?
They are probably already staged. Use git diff --staged.
Whole file shows as changed?
Usually line endings or a formatter. Try git diff -w to confirm, then check your editor's settings.
Habit: run git diff --staged before every commit. It catches debug logs, stray TODOs, and secrets.
08

git pull

Bring your teammates' changes into your branch. It is a fetch followed by a merge (or rebase).

Month 2

Example

$ git pull
$ git pull --rebase       # keep history linear

# when there is a conflict
CONFLICT (content): Merge conflict in src/cart.ts
$ code src/cart.ts       # fix the <<<<<<< markers
$ git add src/cart.ts
$ git commit             # or: git rebase --continue
  • --rebaseReplay your commits on top of the latest remote work.
  • --ff-onlyRefuse anything except a clean fast-forward. Safe default.

Recovery tips

Conflict looks scary, want out?
Abort and you are back where you started: 
git merge --abort
git rebase --abort
Pull finished but something broke?
Git records where you were before the pull: 
git reset --hard ORIG_HEAD
Tip: commit or stash before pulling. Pulling into a dirty working tree makes conflicts harder to untangle.
09

git push

Publish your commits so others (and CI) can see them. This is the moment local work becomes shared.

Month 2

Example

# first push of a new branch
$ git push -u origin fix/cart-total

# after that, just
$ git push

# after amending/rebasing YOUR OWN branch
$ git push --force-with-lease
  • -uRemember the remote branch so plain git push works next time.
  • --force-with-leaseOverwrite only if nobody else pushed in the meantime.

Recovery tips

"Updates were rejected (fetch first)"
Someone pushed before you. Pull, resolve, push again: 
git pull --rebase && git push
Pushed something you should not have?
For a bad change: git revert it and push. For a leaked secret: rotate the credential immediately. Removing it from history is not enough.
Never use plain --force on main or any branch someone else works on. Use --force-with-lease, and only on your own branches.
10

git stash

Park unfinished work so you can switch context (urgent bug, quick review) and come back to it later.

Month 3

Example

$ git stash push -u -m "half-done cart refactor"
$ git switch main         # go fix the urgent thing
$ git switch -            # come back
$ git stash pop

$ git stash list
stash@{0}: On fix/cart: half-done cart refactor
  • -uInclude untracked (new) files too.
  • -m "msg"Label it. Future you will be grateful.
  • applyLike pop, but keeps the stash around.

Recovery tips

stash pop hit a conflict?
The stash is not deleted when pop conflicts. Fix the files, git add them, then git stash drop.
Accidentally dropped a stash?
It is usually recoverable for a while: 
git fsck --unreachable | grep commit
git stash apply <sha>
Gotcha: stashes are easy to forget. If git stash list is longer than three, turn them into branches or delete them.
11

git restore

Throw away changes to a file, or unstage it. The everyday "undo" for work you have not committed yet.

Month 3

Example

# discard edits to one file
$ git restore src/api.ts

# unstage, but keep your edits
$ git restore --staged src/api.ts

# bring back a file as it was on main
$ git restore --source main src/config.ts
  • --stagedOnly touch the staging area.
  • --source <ref>Restore from a branch or commit.

Recovery tips

Restored a file and lost edits you wanted?
If they were never staged or committed, Git cannot get them back. Check your editor's local history (VS Code and JetBrains both keep one).
Deleted a file by mistake?
git restore path/to/file
Warning: git restore <file> without --staged permanently discards uncommitted edits. When unsure, git stash instead; it is reversible.
12

git reflog

Your safety net. Git's private diary of everywhere HEAD has been, including after resets and botched rebases.

Month 3

Example

$ git reflog
7d3e1b2 HEAD@{0}: reset: moving to HEAD~3
a91c4f0 HEAD@{1}: commit: Add checkout tests
5be2d88 HEAD@{2}: commit: Wire up payment form

# "oops, I didn't mean to reset". Go back:
$ git reset --hard a91c4f0

# or rescue it onto a new branch, safely
$ git branch rescue a91c4f0
  • HEAD@{n}Where HEAD was n moves ago.
  • show <branch>History of one branch tip.

When to reach for it

After a bad reset --hard
Committed work is almost never truly gone. Find the SHA in the reflog and reset back to it.
After a rebase went wrong
Find the entry just before "rebase (start)" and reset to it.
Deleted a branch you needed
Find its last commit and recreate it with git branch <name> <sha>.
Limits: the reflog is local only and entries expire (90 days by default). It cannot recover changes that were never committed.

No commands match that search. Try "undo", "branch", or "conflict".

"I did something bad." Now what?

Find your situation, run the fix. First rule: stop, breathe, run git status.

SituationFix
Want to discard edits to a filegit restore <file>Permanent for uncommitted work.
Staged something by mistakegit restore --staged <file>
Bad commit message, not pushedgit commit --amend -m "new message"
Undo last commit, keep the changes, not pushedgit reset --soft HEAD~1
Undo a commit that is already pushedgit revert <sha>Creates a new commit. Safe for shared branches.
Committed to main instead of a branchgit switch -c feature && git switch main && git reset --hard origin/main
Merge or rebase conflict, want outgit merge --abort or git rebase --abort
Push rejectedgit pull --rebase && git push
Reset or rebase destroyed commitsgit reflog then git reset --hard <sha>
Deleted a branchgit reflog then git branch <name> <sha>
Pushed a password or API keyRotate the secret now.Then tell your lead. Rewriting history is a cleanup step, not a fix.

Six habits that prevent most disasters

The commands matter less than the routine around them.

Status before and afterRun git status around every other command. It costs nothing.
Never work on mainBranch for every task, even a one-line fix.
Commit small and oftenCommits are checkpoints. More checkpoints means cheaper mistakes.
Diff before you commitgit diff --staged is your last line of review.
Rewrite only what is yoursAmend, rebase, and force-push only on branches nobody else uses.
Ask earlyA two-minute question beats a two-hour recovery. Everyone has broken Git once.
