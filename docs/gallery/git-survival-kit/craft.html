The git line, first 90 days

Almost nothing in git is permanent.

Twelve commands for your first 90 days, in the order you’ll meet them. Every stop has a way out for the mistake people make there.

DepotDay 0

git clone <url>The line starts here. It doesn’t count as a stop.

You’ll run it once, on day one. It copies the project and its whole history into a new folder. Everything below happens inside that folder, and the reflog starts writing from this moment.

Zone 1Day 1

Your first commit

git statusRun it before every other command.

Stop 01 · Main line

It tells you which branch you’re on, what’s staged for the next commit, what’s changed but not staged, and which files git isn’t tracking yet. It never changes anything, so you can run it fifty times a day.

$ git status
On branch main
Changes not staged for commit:
  (use "git restore <file>..." to discard changes)
	modified:   src/login.js

Untracked files:
	notes.txt

Way out

Lost track of what state you’re in

Run git status and read the lines in parentheses. Git prints the undo command for most states right there.

git addStage files on purpose, not with a dot.

Stop 02 · Main line

Adding moves a change into the staging area, the draft of your next commit. git add . grabs everything, including the debug file you forgot about. Name files, or pick hunks one at a time with -p.

$ git add src/login.js # stage one file
$ git add -p # review each change, answer y or n

Way out

Staged the wrong file

git restore --staged notes.txt unstages it. Your edits stay in the file.

git commitCommit small, and say why.

Stop 03 · Main lineLogged in reflog as “commit”

A commit saves the staged snapshot with a message. Keep each one to a single idea, so it can be read, reviewed, and reverted on its own. The message should explain the change to someone who wasn’t there.

$ git commit -m "Fix typo in login button label"

Way out

Typo in the message, or a file left out (not pushed yet)

Stage the missing file, then git commit --amend --no-edit. Drop --no-edit to rewrite the message.

Committed too early

git reset --soft HEAD~1 takes the commit back and leaves every change staged.

git pullPull before you start, and again before you push.

Stop 04 · Main lineLogged in reflog as “pull”

Pull fetches your teammates’ commits and folds them into your branch. With --rebase your own commits are replayed on top, so history stays a straight line instead of a knot of merge commits.

$ git pull --rebase
$ git config --global pull.rebase true # always rebase

Way out

It stops with CONFLICT

Open the files it names, keep the right lines, delete the <<<<<<< markers, git add them, then git rebase --continue.

You want out of the conflict entirely

git rebase --abort puts everything back as it was before the pull. Pulled with merge instead? git merge --abort.

git pushPush your own branch, never someone else’s history.

Stop 05 · Main line

Push sends your commits to the shared remote. The first push of a branch needs -u to link it to its remote twin; after that, a bare git push is enough.

$ git push -u origin fix-login # first push of a branch
$ git push # every push after

Way out

Rejected: “the remote contains work that you do not have locally”

Someone pushed first. git pull --rebase, then push again.

You amended or rebased a branch you already pushedLoses work

git push --force-with-lease overwrites the remote copy of your branch, and refuses if anyone else pushed to it meanwhile. Never on main.

Zone 2Week 1

Working on a branch

git switchMake a branch for every change.

Stop 06 · Change here for the branch lineLogged in reflog as “checkout”

Branches are cheap: a branch is just a name pointing at a commit. Start each task on a new one so main stays clean and every change can become its own pull request.

$ git switch -c fix-login # create and move to it
$ git switch main # go back to main
$ git switch - # toggle to the previous branch

Way out

You committed to main by accident (not pushed)Loses work

Save the commits on a branch with git branch fix-login, reset main with git reset --hard origin/main, then git switch fix-login. Commit or stash anything unsaved first: --hard discards it.

“Your local changes would be overwritten”

Git won’t switch over unsaved work. Commit it, or park it with git stash (stop 09).

git diffRead your change before anyone else does.

Stop 07 · Branch line

Diff shows line by line what changed. Run it before every commit; reviewers will find the stray console.log if you don’t.

$ git diff # changed, not yet staged
$ git diff --staged # what the next commit will contain
$ git diff main...fix-login # what your branch adds

Way out

It shows nothing, but you definitely changed things

Those changes are already staged; use --staged. Brand-new files don’t appear until you git add them.

git logKnow where you are before you move.

Stop 08 · Branch line

Log lists commits, newest first. The one-line graph view is the version worth memorising: it shows where branches split and where they meet again.

$ git log --oneline --graph -15
* 28ac35e (HEAD -> fix-login) Fix typo in login button
* 187e9ab (origin/main, main) Add login form

Way out

Stuck in a screen with a colon at the bottom

That’s the pager. Press q. Arrow keys scroll, / searches.

Zone 3Weeks 2–4

Parking and discarding

git stashPark unfinished work, briefly.

Stop 09 · Branch line

Stash shelves your uncommitted changes and gives you a clean folder, so you can switch branches or pull. Pop brings them back. A stash older than a week is a branch you forgot to make.

$ git stash push -u -m "half-done header" # with new files
$ git stash list
$ git stash pop # reapply and remove

Way out

Pop stopped with a conflict

Your stash is still safe in git stash list. Resolve the files, then git stash drop it yourself.

git restoreThrow away a change, deliberately.

Stop 10 · Branch line

Restore puts a file back the way it was in the last commit, or the way it is on another branch. It is the right tool when you want a fresh start on one file.

$ git restore src/login.js # uncommitted edits are gone
$ git restore --source=main src/login.js # main’s copy

Way out

You restored the wrong fileLoses work

This is the one git can’t undo. Uncommitted edits were never saved, so no command brings them back, not even the reflog. When unsure, git stash instead: same clean file, with a receipt.

Zone 4Month 2

Undoing in public

git revertUndo pushed work with a new commit.

Stop 11 · Branch line rejoins mainLogged in reflog as “revert”

Once a commit is on a shared branch, don’t erase it. Revert adds a new commit that does the exact opposite, so history stays honest and nobody’s copy breaks.

$ git revert 28ac35e
[main 24865e2] Revert "Fix typo in login button"

Way out

The bad commit is a merge

git revert -m 1 <sha>. The 1 tells git to keep main’s side and undo what the merge brought in.

You reverted the wrong commit

Revert the revert. It’s a commit like any other.

Zone 5Day 90

Or your first bad day

git reflogFind the commit you think you lost.

Stop 12 · Change here for the ghost line

Every time HEAD moves (a commit, a pull, a switch, a reset) git writes it down. The reflog is that diary. A commit no branch points to still lives here, and you can put a branch back on it.

$ git reflog
9c1d2e4 HEAD@{0}: reset: moving to HEAD~1
b7a3f10 HEAD@{1}: commit: Add password check
9c1d2e4 HEAD@{2}: commit: Fix typo in login button
4e8f2a1 HEAD@{3}: checkout: moving from main to fix-login

$ git branch rescue b7a3f10 # back on a branch

Way out

A reset ate your work

Find the line just before the reset, then git branch rescue <sha>. Safer than resetting again: nothing else moves.

How long you have

Entries stay 90 days by default, but only 30 for commits no branch can reach. Lost something? Act within the month. The reflog lives on your laptop only.

End of the line. You’ll stop needing the map around day 90.

That’s also how far back the reflog remembers. If something goes wrong before then, the way out is almost always on this page: read git status, then come back to the stop you were at.

P.S. Before you try anything clever on a repo you’re scared of, copy the whole folder: cp -r acme-web acme-web-backup. It isn’t a git command. It’s still the one undo that works when you’ve misunderstood everything.

Commands, flags, and messages checked against Git 2.50.1 and its manual pages on 22 October 2026. git switch and git restore arrived in Git 2.23 (August 2019) to split up the overloaded git checkout; their manuals still say “experimental,” though git status already points you to restore.
