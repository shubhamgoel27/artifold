Transformers, from the point of view of someone who already knows LSTMs and CNNs

You already know how to move information along a sequence: recurrence passes it step by step, convolution passes it neighborhood by neighborhood. Self-attention passes it directly, between any two positions, with weights computed from the content itself. Everything else in the Transformer is engineering around that one idea.

1What is wrong with recurrence and convolution

An LSTM summarizes the past into a fixed-size state and updates it one token at a time:

ht= f(ht−1,xt)

Two consequences follow. First, computing ht requires ht−1, so the n steps of a sequence are inherently serial; a GPU with thousands of cores waits on a chain of length n. Second, for token 50 to influence token 1, the signal must survive 49 multiplicative updates in the forward pass and 49 Jacobians in the backward pass. Gating helps a lot, but the path length is still O(n).

A 1-D convolution fixes the parallelism problem: every output position is computed independently.

yi= ∑k=−rr Wkxi+k

But the receptive field grows only linearly with depth (or logarithmically with dilation), so connecting distant tokens takes a stack of layers. More subtly, the kernel Wk is fixed after training: the weight between position i and i+2 is the same regardless of what words are actually there.

The wish list. We want (a) every position computed in parallel, like a conv; (b) any position able to read any other in one step, unlike both; and (c) the mixing weights to depend on content, not just relative offset. Self-attention delivers all three.

2Attention as a soft dictionary lookup

Picture a Python dict. You present a query, it is compared against every key, and the value of the exact match is returned. Attention is the differentiable version: compare the query to every key with a similarity score, turn the scores into a probability distribution, and return the weighted average of all values.

In self-attention, every token plays all three roles at once. Token i has an embedding xi∈ℝdmodel, and three learned linear maps project it into a query, a key, and a value:

qi=xiWQ, ki=xiWK, vi=xiWV WQ,WK∈ℝdmodel×dk, WV∈ℝdmodel×dv

Intuitively: the query is "what am I looking for?", the key is "what do I contain, for the purpose of being found?", and the value is "what I hand over if you pick me." Separating key from value matters: a pronoun might be found because it is a noun-phrase slot, but what it should contribute is information about its referent.

For a single position i, the output is:

αij= exp⁡(qi·kj/dk) ∑l=1nexp⁡(qi·kl/dk) , zi= ∑j=1n αijvj

Each row αi,: is a probability distribution over the n positions. If you have seen Bahdanau attention in an LSTM encoder-decoder, this is the same mechanism, with two changes: the score is a scaled dot product rather than a small MLP, and the queries come from the same sequence as the keys (hence "self").

A tiny worked example

Take the sentence "the cat sat", and suppose for token "sat" the scaled scores against (the, cat, sat) come out as (0.1, 2.0, 0.6). Softmax gives roughly (0.11, 0.72, 0.18), so "sat"'s new representation is 0.11vthe+0.72vcat+0.18vsat. The verb has pulled in information about its subject in a single step, and it did so because the contents of "cat" matched what "sat" was asking for.

3Scaled dot-product attention, in matrix form

Stack the token embeddings into X∈ℝn×dmodel. Then Q=XWQ, K=XWK, V=XWV, and all n outputs come from one expression:

Attention(Q,K,V)= softmax ( QK⊤dk +M ) V

Shapes: Q (n × d_k) · Kᵀ (d_k × n) → scores (n × n) → softmax row-wise → (n × n) · V (n × d_v) → output (n × d_v). M is an optional (n × n) mask, covered in §9.

That is two matrix multiplies and a softmax. No loop over time. This is the whole reason Transformers train so fast on GPUs: the work that an LSTM spreads across n sequential steps becomes one dense n×n matmul.

Why divide by √dk?

Suppose the components of q and k are roughly independent with mean 0 and variance 1 (which is what a sensible initialization plus normalization gives you). Then

q·k=∑m=1dkqmkm ⇒ 𝔼[q·k]=0, Var[q·k]=dk

With dk=64, raw scores have a standard deviation of 8. Feeding numbers that spread into a softmax produces a nearly one-hot distribution, and the softmax gradient αj(δjl−αl) goes to zero almost everywhere. This is the same saturation problem you know from sigmoid gates in an LSTM. Dividing by dk brings the variance back to 1.

4Attention as a dynamic convolution

Here is the framing that tends to click for people with a CNN background. Write a conv and self-attention side by side, both as "output at i is a weighted sum of transformed inputs":

Convolution: yi=∑j Wj−i⏟depends on offset only xj Self-attention: yi=∑j αij(X)⏟depends on content xjWV

In a convolution the mixing weights are parameters, indexed by relative offset, shared across positions, and confined to a small window. In attention the mixing weights are activations: computed fresh for every input, spanning the whole sequence, and indexed by what the tokens say rather than where they sit. The learned parameters (WQ,WK) only define how to compute the kernel.

Inductive bias trade. A conv bakes in locality and translation equivariance, which is why it is data-efficient on images. Attention bakes in almost nothing; it is permutation-equivariant and must learn locality from data. That is why Transformers tend to need more data, and why positional information has to be added explicitly (next-but-one section).

5Multi-head attention

One softmax produces one distribution per query, so a single attention layer can only "look" one way at a time. But a token often needs several kinds of information simultaneously: its syntactic head, its coreferent, the previous token. The fix is the attention analogue of having multiple conv channels: run h attentions in parallel with separate projections, each in a smaller subspace, then concatenate.

headi= Attention( XWiQ, XWiK, XWiV) MultiHead(X)= Concat(head1,…,headh)WO

With dk=dv=dmodel/h (e.g. 512 / 8 = 64 in the original paper) and WO∈ℝhdv×dmodel, the total cost is about the same as one full-width head. In practice all heads are computed in one batched matmul by reshaping (n,dmodel)→(h,n,dk).

6Where did the order go? Positional encoding

Look at the attention formula again: nothing in it refers to position. Permute the rows of X and the rows of the output permute identically. To a bare attention layer, "dog bites man" and "man bites dog" are the same bag of tokens. An LSTM gets order for free from recurrence; a conv gets it from the kernel's offset indexing. The Transformer has to inject it.

The original paper adds a fixed sinusoidal vector to each embedding:

PE(p,2i)= sin⁡(p100002i/dmodel) PE(p,2i+1)= cos⁡(p100002i/dmodel) xpin=Embed(tokenp)+PEp

Each pair of dimensions is a clock running at a different frequency, from period 2π up to 10000·2π. The useful property: for any fixed offset Δ, PEp+Δ is a rotation of PEp (per frequency pair), so a linear map can learn to attend "3 tokens to the left" regardless of absolute position.

Modern models mostly use RoPE (rotary position embeddings) instead, which takes this idea to its conclusion: rather than adding position to x, it rotates each query and key by an angle proportional to its position, so the score qi·kj depends only on content and the relative offset i−j. That recovers some of the conv's relative-position bias without giving up global reach.

7The rest of the block: FFN, residuals, LayerNorm

Attention mixes across positions but is nearly linear in the values: it is a weighted average. The non-linear computation happens in a position-wise feed-forward network applied independently to every token. If you like, it is a 1×1 convolution with a hidden layer:

FFN(x)= max⁡(0,xW1+b1)W2+b2 , W1∈ℝdmodel×4dmodel

A useful mental model: attention is communication, the FFN is computation. Tokens exchange information in the attention sublayer, then each token thinks about what it received in the FFN. Roughly two thirds of a Transformer's parameters live in the FFNs. (Modern variants swap ReLU for GELU or a gated SwiGLU, but the role is the same.)

Each sublayer is wrapped in a residual connection and layer normalization:

LayerNorm(x)= γ⊙x−μσ2+ε+β (μ, σ² over the feature dimension of one token) Post-LN (original): x←LN(x+Sublayer(x)) Pre-LN (modern): x←x+Sublayer(LN(x))

The residuals do for depth what the LSTM's additive cell update does for time: they give gradients an identity path, so a 96-layer stack trains the way a ResNet does. LayerNorm, rather than BatchNorm, normalizes each token's vector on its own, which works with variable-length sequences and tiny per-device batch sizes. Pre-LN keeps the residual stream completely clean and is markedly more stable to train at scale, which is why almost every large model uses it.

8The full architecture

The original Transformer ("Attention Is All You Need", Vaswani et al., 2017) is an encoder-decoder for translation, shaped just like a seq2seq LSTM but with every recurrence replaced by attention. The diagram shows the post-LN layout from the paper.

Read it as you would a seq2seq LSTM:

  • Encoder: embed the source tokens, add positions, then apply N blocks of [self-attention → add&norm → FFN → add&norm]. The output is one contextualized vector per source token. Unlike an LSTM encoder, there is no single "thought vector" bottleneck; the decoder sees all n of them.
  • Decoder: embed the target tokens generated so far, then apply N blocks of [masked self-attention → cross-attention to the encoder → FFN], each with residual + norm.
  • Head: a linear map to vocabulary size and a softmax give p(yt∣y<t,x). Training minimizes cross-entropy ℒ=−∑tlog⁡p(yt*∣y<t*,x) with teacher forcing, exactly as you would for an LSTM decoder.

Two descendants dominate today. Encoder-only models (BERT) keep just the left tower and train it to fill in masked tokens. Decoder-only models (GPT, Claude, Llama) keep just the right tower minus the cross-attention, so each block is masked self-attention plus FFN, trained to predict the next token.

9Masking and cross-attention

The causal mask

An LSTM decoder is causal by construction: ht cannot see xt+1 because it has not been computed yet. Self-attention sees the whole sequence at once, so during training position 3 could simply read the answer from position 4. The mask M in the attention formula forbids it:

Rows are queries, columns are keys. Grey cells are masked to −∞ before the softmax. Shading is an illustrative attention pattern ("it" attends to "cat").

The payoff is large: one forward pass over a length-n target computes all n next-token predictions in parallel, each of which only saw its own prefix. An LSTM needs n sequential steps for the same thing.

At inference you still generate one token at a time. To avoid recomputing everything, implementations cache each layer's K and V for past positions (the KV cache); each new token computes just its own q,k,v and attends over the cache. The cache plays the role of the LSTM's hidden state, except that it grows with the sequence instead of being fixed-size, which is both the source of the Transformer's memory and its main inference cost.

Cross-attention

Cross-attention is the same formula with queries from one sequence and keys/values from another. In the decoder, Q comes from the decoder's own stream and K,V come from the encoder output H:

CrossAttn(Ydec,H)= softmax ((YdecWQ)(HWK)⊤dk) HWV

This is exactly the Bahdanau/Luong attention you may have bolted onto an LSTM translator: "for the word I am about to produce, which source words matter?" No mask is needed, because the whole source is legitimately available.

10Cost: what you buy and what you pay

This is Table 1 of the original paper, with n the sequence length, d the representation width, and k the kernel size.

Layer typeCompute per layerSequential opsMax path length
Self-attentionO(n2·d)O(1)O(1)
Recurrent (LSTM)O(n·d2)O(n)O(n)
ConvolutionalO(k·n·d2)O(1)O(logkn) (dilated)

Self-attention buys constant path length and full parallelism. It pays with the n2 term: the score matrix has one entry per pair of tokens. When n<d (sentences, with d in the hundreds or thousands) attention is actually cheaper than a recurrent layer. For long documents, the quadratic term dominates, which motivated FlashAttention (same math, computed in tiles so the n×n matrix never sits in memory), sparse and sliding-window attention, and linear-time alternatives such as state-space models, which in a sense bring the recurrence back.

The real reason it won. Not any one formula, but that every operation is a large dense matmul with no sequential dependency during training. That maps perfectly onto GPU/TPU hardware, so for a fixed compute budget you can train far bigger models on far more data than with an LSTM. Scale did the rest.

11The whole thing in ~40 lines

A decoder-only (GPT-style) block in PyTorch, pre-LN. Everything above, nothing hidden:

import math, torch, torch.nn as nn, torch.nn.functional as F

class MultiHeadSelfAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        self.h, self.d_k = n_heads, d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model)   # W^Q, W^K, W^V fused
        self.out = nn.Linear(d_model, d_model)       # W^O

    def forward(self, x, causal=True):
        B, n, d = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        # (B, n, d) -> (B, h, n, d_k): every head in one batched matmul
        q, k, v = (t.view(B, n, self.h, self.d_k).transpose(1, 2) for t in (q, k, v))
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.d_k)       # (B, h, n, n)
        if causal:
            mask = torch.triu(torch.ones(n, n, dtype=torch.bool, device=x.device), 1)
            scores = scores.masked_fill(mask, float("-inf"))         # M_ij = -inf for j > i
        attn = F.softmax(scores, dim=-1)                             # rows sum to 1
        z = attn @ v                                                 # (B, h, n, d_k)
        z = z.transpose(1, 2).reshape(B, n, d)                       # concat heads
        return self.out(z)

class Block(nn.Module):
    def __init__(self, d_model=512, n_heads=8):
        super().__init__()
        self.ln1, self.ln2 = nn.LayerNorm(d_model), nn.LayerNorm(d_model)
        self.attn = MultiHeadSelfAttention(d_model, n_heads)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, 4 * d_model), nn.GELU(), nn.Linear(4 * d_model, d_model))

    def forward(self, x):
        x = x + self.attn(self.ln1(x))   # communicate across tokens
        x = x + self.ffn(self.ln2(x))    # compute per token
        return x

# A full model: token embedding + positional embedding -> N blocks -> LayerNorm -> Linear to vocab.
# Train with F.cross_entropy(logits[:, :-1], tokens[:, 1:]), i.e. next-token prediction.

In production you would replace the four lines from scores to attn @ v with F.scaled_dot_product_attention(q, k, v, is_causal=True), which dispatches to a fused FlashAttention kernel. The math is identical.
