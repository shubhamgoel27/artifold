A manifesto in twelve points

Slow Software,
on purpose.

For tools that open instantly, keep your work in files you can see, and are still there in ten years. Software should be a quiet instrument, not a subscription to someone else's roadmap.

  1. Keep the work in files.

    Plain text, a format with a published spec, a folder you can open in any file browser. If the only way to reach your writing is through an app that is still running, on servers that are still paid for, by a company that still exists, you do not own it. You are renting it.

  2. Work offline first.

    The network is a feature, not a foundation. Software that launches on a plane, saves without a connection, and syncs when it can is software that trusts the person in front of it more than the cloud behind it.

  3. Count dependencies like debts.

    Every package you install is a stranger with commit access to your product. You pay interest on it in upgrades, audits, and surprise breakage. Borrow only when writing the thing yourself is genuinely worse, and write down why.

  4. Choose boring formats.

    Markdown, CSV, JSON, .sqlite, PNG. A format that dozens of tools can read will outlive the tool that wrote it. Cleverness belongs in the program, never in the file.

  5. Do one thing, then stop.

    A text editor does not need to become a chat app, a calendar, and a social feed. Scope is a promise to your users. Finished is a feature, and it is the rarest one in our industry.

  6. Change slowly.

    Every redesign spends your users' attention without asking. Muscle memory is a gift you gave them; do not take it back to hit a quarterly goal. Move a button only when moving it is clearly, measurably kinder.

  7. Make it fit in one head.

    If no single person can explain how the whole system works, nobody can fix it at three in the morning. Smallness is not nostalgia. It is a security property, a reliability property, and a kindness to whoever maintains it next.

  8. Respect the machine.

    A note-taking app does not need two gigabytes of memory and a bundled browser. Measure startup time, memory use, and download size. Treat every regression as a bug, because to the person on an old laptop, it is one.

  9. Never demand an account for local work.

    Asking someone to sign in before they can open their own file is a toll booth on their front door. Identity belongs to sharing and syncing, and only when the user chooses either.

  10. Leave the door open.

    Export everything, in a documented format, in one step. The surest way to earn loyalty is to make leaving painless. Lock-in is an admission that the product could not keep people on its merits.

  11. Delete more than you add.

    Features carry a cost long after the launch post fades. Retire what nobody uses, collapse what overlaps, and celebrate the pull request that removes a thousand lines. Code you delete can never break.

  12. Build it to be finished.

    Aim for a 1.0 that could honestly be the last release. Maintenance should mean fixing bugs and keeping the lights on, not feeding a treadmill of updates. The best software is the kind you forget is software at all.

None of this is new. Most of it is simply old enough to have been forgotten.

Print it. Save it. It is one file, and it will still open long after the frameworks have moved on.
